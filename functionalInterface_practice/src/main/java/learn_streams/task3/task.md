## Задание 3. Ленивая инициализация с использованием Supplier
### Контекст
`Supplier<T>` — это функциональный интерфейс, который не принимает аргументов, но возвращает значение. <br>
Он часто используется для отложенных (ленивых) вычислений, когда значение может быть дорогим или не всегда нужным.

#### Задача
Создай класс `Lazy<T>`, который хранит `Supplier<T>` и вычисляет значение только один раз при первом запросе (паттерн ленивая инициализация с потокобезопасностью).<br>
Класс должен иметь:<br>

Конструктор, принимающий `Supplier<T>`.<br>

Метод `T get()`, который возвращает результат (если ещё не вычислен — вызывает `supplier`, сохраняет и возвращает; если уже вычислен — возвращает сохранённое значение).

(Опционально) Метод `boolean isInitialized()`.

Используй этот класс для демонстрации:

Создай 
```java
Lazy<String> heavyResource = new Lazy<>(() -> {
    System.out.println("Вычисляем тяжёлый ресурс...");
    return "Данные после долгой загрузки";
});
```

Вызови `get()` несколько раз и убедись, что `supplier` выполняется только один раз.<br>

Покажи, что если объект Lazy никогда не используется, то `supplier` не вызывается.<br>

Усложнение: Сделай потокобезопасную версию (можно использовать `volatile` и `synchronized`, или `AtomicReference`, или даже `ConcurrentHashMap`).<br>

Объясни, почему в многопоточной среде простая проверка if (value == null) может быть опасна.
