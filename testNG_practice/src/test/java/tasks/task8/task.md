## Задача 8. «Параллельный запуск и потоки» (IInvokedMethodListener + parallel)
### Цель:
Увидеть, как `TestNG` распределяет тесты по разным потокам, и научиться отслеживать это в логах.

#### 📌 Инструкция
- В testng.xml укажи параллельный запуск методов:
  `<suite name="Parallel Suite" parallel="methods" thread-count="3">`
- Создай 6 тестовых методов, каждый из которых спит 1 секунду и печатает название потока.
- Используй уже знакомый `ExecutionTimer (IInvokedMethodListener)`, добавив в вывод ID текущего потока:
  `Thread.currentThread().getId()`

Увидишь, что слушатель фиксирует запуск в разных потоках.

#### 🧩 Задание с изюминкой
- Попробуй снять параллельность и запустить ту же сюиту — как изменится порядок и время выполнения?
- Подумай, зачем слушателю знать ID потока? (для отладки проблем многопоточности, если тесты мешают друг другу)


## Что дальше? Рекомендации и ресурсы
Ты только что применил на практике ключевые механизмы расширения `TestNG`. Теперь попробуй:

- Соединить всё в одном проекте: один `testng.xml`, куча слушателей, параллельное выполнение, отчёт с группировкой результатов по группам.
- Изучить другие слушатели: `ISuiteListener` (события на уровне всего набора), `IConfigurationListener` (отдельно для `Before/After` методов).
- Почитать документацию `TestNG`: раздел `Listeners` — там есть примеры и полный список интерфейсов.
- Практический кейс: Создай мини-фреймворк для тестирования `API` с автоматическим логированием запросов/ответов при падении теста, используя слушатель.
