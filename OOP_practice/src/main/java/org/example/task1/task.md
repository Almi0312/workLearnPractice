## Задача 1. Система уведомлений (Паттерн Strategy)
### Контекст (реальная ситуация):
Ты делаешь бэкенд для интернет-магазина. Пользователь может получать уведомления о статусе заказа: 
по `email`, `SMS` или через push-уведомление в приложении.<br>
Сейчас код выглядит так:

```java
if (type.equals("email")) {
sendEmail(...);
} else if (type.equals("sms")) {
sendSms(...);
} else if (type.equals("push")) {
sendPush(...);
}
```
### Проблема:
Каждый раз, когда добавляется новый способ (например, `Telegram`), приходится лезть в этот `if` и менять код. 
**Это нарушает принцип открытости/закрытости** (класс открыт для расширения, но закрыт для изменения).

### Задача:
Спроектируй классы так, чтобы:
- Можно было легко добавить новый канал уведомлений, не трогая существующий код.
- В основном классе-отправителе был только вызов `notifier.send(message)`.

### Что ты должен показать в решении:
- Интерфейс `NotificationStrategy` с методом send(String message).
- Конкретные классы: `EmailStrategy`, `SmsStrategy`, `PushStrategy`.
- Класс `NotificationService`, который получает стратегию в конструкторе (или через setter) и делегирует ей отправку.
